# Describe the actual appearance choices

Avatar radios retain their ordinal and now describe the actual face shape, skin
palette and visible hair style/colour of that preset. The custom first slot uses
its current traits, rather than describing the original first preset. Bald
previews omit the stored hair colour because that colour is not visible; its
saved value remains intact. The six existing skin swatches retain their ordinal
and add neutral palette descriptions from very light through deep brown.
Hair-style, hair-colour and face-shape choices retain their existing names and
checked state. No gender, race, clothing, biography or other trait is inferred.

The Life profile button also describes its actual visible name, age, occupation
and bank balance. Visual and accessibility output share the same single existing
localized money format. Only this button's nested portrait becomes decorative;
other standalone portraits keep their existing image role and person label.
Profile navigation is unchanged.

This later UI branch starts from frozen C37 `a4be96e` and does not alter that
accepted worktree. Assets, source rectangles, palette colours, presets, IDs,
defaults, radio selection, creation commands, saves, game rules and versions
are unchanged. The extra text is an accessibility presentation improvement.

Focused acceptance checks real distinct presets, all six swatch mappings, the
actual custom slot, invisible bald colour omission, native checked metadata,
unchanged other draft fields and Continue behaviour. The original creation
flows retain their saved identity/appearance and database assertions. The
genuine employed US fixture supplies a nonzero balance/occupation/age header,
and the original Japanese newborn flow checks its zero JPY/newborn label.
Standalone portrait accessibility remains separately covered. These are
component-label checks; actual TalkBack/VoiceOver speech and native layouts
remain unclaimed.

(`/tmp/dreams-appearance-semantic-focused.out`). Strict application types and the
affected four-test import graph both closed with exit0 and empty logs
(`/tmp/dreams-appearance-semantic-app-types.out` and
`/tmp/dreams-appearance-semantic-test-types.out`). Existing connected creation
checks retain their original in-memory/on-disk database scopes; the new label
cases themselves are component/draft checks and a read-only genuine fixture.
No full regression, all-test typecheck, export, new native capture or speech
test was performed for this isolated UI branch.
