# Retirement-move money proof: read-only WIP review

This is a narrow source review of uncommitted work in `/workspace/dreams-worktrees/npc-retirement-moves`, not exact-SHA implementation approval. No reviewer engine commands, tests, SQLite, native or fixtures were executed or edited. C37 remains separate.

The proposed historical moving-money proof is coherent: it retains the native owner/account, pre-attempt ledger cursor and cash, frozen V1 fee/living/reserve, and exact next moving-payment row only on success. Validation reconstructs historical cash from opening cash plus a single ordered ledger-prefix sweep, including stayed outcomes, without requiring today's balance or household members to equal the historical snapshot. Pension periods are counted from real positive receipt rows preceding the saved tax boundary, not the migrated pension-month counter.

Both Work and this reviewer independently found an eager-account regression: the first tax wrapper called `accountFor` for every financial actor before original `settleTax`, although a zero-cycle original settlement needs no account. The author's current WIP now calls the original settlement first in the original actor order and returns no move proof when an existing native account is absent. It creates no account and expands no financial-actor set. Final frozen source/equivalence tests remain pending.

Remaining validation gap: saved tax `gross/withheld/due` can all become zero with an arbitrary later empty ledger span and null payment. That currently passes despite a linked current regular pension contributing positive gross/withholding. An empty span proves no independent actual settlement by itself.

Bounded recommendation sent to root/author/Work: require the linked current regular pension's actual `income` receipt (not a catch-up `background-income` receipt), require captured tax gross/withheld to cover that known contribution, and retain a reference to the original unchanged settlement's finance journal row. Check actual person/date and exact captured gross/due text against that existing row, with position/identity binding to the same settlement command. Do not create another tax journal or payment. This supports actual captured settlement-artifact and known-pension consistency; it does not independently reconstruct every taxable cycle from ledger cash.

Full taxable-cycle reconstruction from generic positive cash rows would be wrong: sales proceeds differ from capital gains, wages/royalties can be converted, and background pensions are settled differently from regular cycle gross. Root decides proof strength before final implementation approval. Negative cases should preserve a real zero-adjustment positive-pension settlement while rejecting zeroed metadata, relocated empty spans and substituted/missing original settlement artifacts. No outcome, tax, pension, history or acceptance is fabricated by this review.
