# Incremental ledger checkpoint

The model now owns a private ledger-index certificate, issued only after complete world validation and freezing. A verified append extends transaction/position lookups through a persistent hash trie and updates small exact BigInt balance/reference maps. Category blocks preserve append order. Existing-row changes, removals and reorders rebuild. Standalone frozen arrays cannot seed or access the model cache. Duplicate IDs are checked against both old history and the append batch. All original reconciliation and cross-system checks still run.

The original copy engine remains the production default. An isolated plain-data draft prototype and comparative entry point are present for the next measured checkpoint. It handles nested mutation, array operations, deletions, BigInt, raw newly inserted objects, retained local references, rollback and proxy revocation. Its outputs are recursively frozen plain data; no publication can retain a live proxy. Draft provenance permits a future verified prefix without a historical scan; the current copy path proves every old ledger position while parsing.

Seven samples after warm-up on the same retained input checkpoints; routine/finance include acknowledgement. Separate host runs are descriptive, with mixed small cases. At age 23 extreme, finance p50 is 43.2 → 37.9 ms; at 70 light, 97.0 → 68.4 ms; at 70 extreme, 91.1 → 85.4 ms. Complete-year medians are 293.7 → 263.9 ms at 23 extreme and 514.6 → 447.1 ms at 70 extreme. All 12 matched scenarios retain identical command hashes, complete canonical-world hashes, RNG and **checkpoint SHA-256**, not just byte counts. Raw samples: `ledger.json.gz`.

Strict app/test types and six focused suites / 50 tests pass. Tests include exact ordering/positions, arbitrary legacy IDs, duplicate IDs, very large BigInts, independent prior indexes, mutable/frozen forgeries, balance/reference corruption, nested drafts, every-command twelve-year canonical/RNG/checkpoint comparison, and the existing copy/branch/JSON cache suites. Full regression, 120-life soak, compatibility/SQLite and native-device acceptance remain required after the remaining architectural changes. No save-format, gameplay or RNG change is introduced here.
