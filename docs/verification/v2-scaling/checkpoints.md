# Reusable checkpoint history

The measured main-body encoding cost justified a narrow v5 checkpoint: journal and relationships are independently compressed immutable 128-record blocks. The existing ledger tuples, people chunks, gzip settings, hash checks, atomic SQLite writes, backups, snapshots and receipts remain. A new tail block is encoded on append; full old history blocks reuse their encoded bytes after exact identity/order checks. Small worlds keep the existing v1/v4 writer. `packCheckpointV4` retains the prior byte-compatible reference writer. No tables, command log or event-sourcing architecture is added.

The reader retains v1, v2, v3 and v4, enforces per-part/combined/expanded-size limits, verifies compression trailers and content hashes, rejects malformed history partitions and body collisions, then runs complete world validation before granting any certificate. Canonical decoded worlds and deterministic same-version output are required across the intentional version change; different codec versions do not promise identical bytes. Retained snapshots/backups keep their original immutable payloads. No old fixture is rewritten.

SQLite reader marker 33 prevents older reader-32 binaries from writing an unsupported v5 database. Compatible eight-table reader 13–32 databases update only this metadata marker, in an atomic transaction. Reader 34 is refused before any write. Existing migration assertions now target reader 33 and future 34; historical stored rows/payloads are unchanged. Both reader 31 and 32 metadata rollback/retry are covered.

Seven-sample host prototype comparisons, against the structural-sharing checkpoint: age 23 extreme routine 26.0 → 19.8 ms, finance 33.5 → 20.7 ms and complete year 216.4 → 189.2 ms. At age 70 extreme, routine 56.5 → 45.4 ms, finance 69.4 → 56.8 ms and complete year 409.6 → 289.9 ms. Young/light timings are mixed, including regressions under concurrent host load. These separate runs justify the targeted history format, not a phone-speed claim. Raw results: `checkpoint-prototype.json.gz`; all twelve canonical/RNG/command outcomes match the previous codec.

Twelve new codec/SQLite cases pass on genuine long-running legacy history: deterministic round-trip; append reuse and edited-history invalidation; hash/size/body/partition corruption; duplicate/missing-person/future-date history; failed transaction, exact retry, idempotency, closed-connection reopening, backup, export and independent snapshot branch. Legacy tuple and fragment suites are rerun. Two natural-save assertions were deliberately updated to expect the new writer version, while the original legacy payload remains byte-for-byte intact. Final integrated regression, soak, exports and physical-device acceptance are reported separately.
