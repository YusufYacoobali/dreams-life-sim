## Concrete release defects corrected

- `app.config.cjs` hardcoded testing God Mode on in every build, including stores. Production profile **or** store distribution now forces `extra.godModeTesting=false`, even if a testing environment flag or inherited config extra requests access. Internal, preview and development profiles retain testing access; unmarked local release builds default off. An explicit non-store testing flag remains available. `eas.json` marks production/store testing off explicitly. Runtime development access, saved settings, edited values and edit history are unchanged. Existing route, shortcut, preferences-ready and store-command checks remain in force; the mini-game playground uses the same access guard.
- The Expo Android template requests overlay and legacy broad-storage access; `expo-file-system` also contributes the latter through its library manifest. `app.json` now blocks `SYSTEM_ALERT_WINDOW`, `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE` and `RECORD_AUDIO` at manifest merge. Dreams imports/exports through the system file/directory pickers, URI grants and app cache sharing; no app path requests broad storage or overlay access. Notifications remain allowed. No exact-alarm or full-screen permission was added.
- Expo's native `isAvailableAsync` checks `PackageManager.getPackageInfo` for Play Store, but neither the app's initial manifest nor the inspected Review/Play Services AAR manifests supplied a Play Store package query. `withStoreReviewVisibility.cjs` now adds only `com.android.vending`, preserving existing package/intent/provider queries and adding no permission. This prevents Android 11+ sideloaded/internal APKs from reporting Play unavailable merely because of package visibility. Play-installed builds may already see their installer automatically, so this does not establish that all Play releases were broken. [Actual artifact URLs, AAR/manifest hashes and inspected query results](play-review-visibility.json) cover fourteen AARs, including Review `2.0.1`, Review KTX `2.0.0`, Core Common `2.0.2` and the newer Play Services requested by Firebase Messaging `25.0.1`; no downloaded AAR is committed. Final merged-manifest and installed behavior still require the release build.

Regression coverage authored: `tests/state/god-mode-access.test.ts`, `tests/ui/god-mode-flow.test.tsx` and `tests/config/release-config.test.ts`. The config suite resolves Expo configuration for production/internal/preview/local permutations and exercises Expo's actual blocked-permission mutator. The real SQLite UI suite now tests an actual production configuration, an inherited testing environment flag and an enabled saved toggle together, verifying that direct edits remain denied without changing the save. Existing Saved Lives file-picker/share suites cover the retained storage paths. `git diff --check` passed at this agent's source freeze; root runs the suites and native configuration checks.
