known contacts. It starts with the genuine age-30 checkpoint already used by the
button benchmark, then calls the production contact/background/relationship
functions. This generated-at-once setup is explicit; it is not a natural or native
journey. Saved NPC draws, qualifications, household accounts and work history
remain real domain data. All twelve country profiles occur among the new contacts.
Only the financially relevant cohort receives full monthly accounting; this is
not a claim that every known person has a separate monthly ledger.

warm-up and five fixed-input engine/SQLite samples. Every cold current and backup
must match. The Age Up cases also retain the original Before Age Up payload,
and report actual processed months/stage. These are cloud diagnostics, with no
physical/native p95 or complete 120-year/storage acceptance inferred.

rather than running the schema parser again before the action. All mutable nested
objects are isolated, including other people's data. Only the existing certified
immutable ledger rows are shared. Every command result still passes complete
shape, financial and cross-system validation before publication. A frozen or
shallow-copied untrusted object cannot enter the certified path.

repeatedly scanning the whole history for each person's current contract and
earnings totals. Every history row and original integrity condition is still
checked. The index is local to that validation, with no stale cross-save cache.
