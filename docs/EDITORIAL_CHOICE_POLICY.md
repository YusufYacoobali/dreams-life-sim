## Registered strategy

Each new life starts with the actual in-memory SQLite repository/store
`startLife` and saved `acknowledgeBirth`, using ordinary creation, country's
first city and birth date2000-01-01. No saved flag or other world field is edited.
The only later commands are validated immutable-engine `advance`, `resume`,
`choose` and `acknowledge`. SQLite is used for birth only: later progression is
pure engine with production checkpoint recovery, not a SQLite/native journey.
There are no optional job/family/asset/hobby setups or overrides of money,
stats, age, dates, RNG, consent, outcomes or survival.

At each actual pending decision, evaluate `choiceUnavailable` on its existing
ordered bound choices. Select `eligible[decisionOrdinal % eligible.length]`.
The zero-based ordinary decision ordinal starts at0 for each life and increases
only after a successful committed `choose`; system and callback decisions also
consume it. Three currently available options therefore rotate positions1,2,3.
Filtering can make eligible position2 authored branch3; both indexes and all
actual reasons are retained. No hidden roll informs selection. Stored outcome
fields may be logged for evidence but never determine the chosen option.

The offered scene retains its actual ID, text, participants and effects. It is
never rebound, and `eligibleTemplates` is not rerun against a scene already
recorded in history. Catalogue membership uses the exact source's template IDs.
Catalogue scenes check actual age range, one origin in the current year and at
least five years since prior occurrences. Interviews, medical decisions and
story callbacks remain separate from the250-template catalogue.

The driver retains full bound choices and eligibility, selected authored/eligible
positions, actual pending/deferred results, new journal entries, callback thread
bindings, origin/resolution IDs and before/after actual participant
stats/grades/skills, affected relationships and accounts. These snapshots support
capped-consequence comparisons without inventing intended deltas. Annual records
retain progression and actual history/threads, and distinguish a reached target
date from a final partial year interrupted by natural death.

Production `packCheckpoint` / `unpackCheckpoint` replaces the active world with
the loaded immutable world, checking complete canonical equality at each distinct
pending decision/result revision, annual closure and final state. Reusing a check
at the same revision does not omit queued data: the complete world, including
pending/deferred scenes, is serialized. Production chooses its existing frame
format; small worlds correctly usev1. Natural death must retain a valid cause and
one estate, matching currencies and conservation including written-off debt.
Early death remains an observed outcome. Every unseen template and unchosen
catalogue branch is listed; no all250, all750, all-context, full Scenario A/B/C,
120-year, native, physical-device or multigeneration claim is made.

## Source selection and artifacts

`tools/run-editorial-policy.cjs` requires `--source ABSOLUTE_C35_WORKTREE` and
loads the engine, model, choices, event catalogue, checkpoints, store, repository,
creation and SQLite birth driver from that same source tree. Only the new policy
helper comes from the tool's tree. It rejects mismatched C35 game/persistence,
all-state, store, birth-driver or lockfile fingerprints. It records checkout HEAD
separately from the reference commit: subsequent tool/documentation commits need
not change the reviewed production game. Every source pin, including tool and
helper, is checked before/after loading and after each life and cohort. Node and
TypeScript versions are recorded.

A manifest-only command creates no life or output directory:

```sh
node tools/run-editorial-policy.cjs --source /absolute/path/to/frozen-C35 --manifest-only
```

A run requires explicit `--country CODE` or `--all` and an empty external
`--output DIRECTORY`. `--max-years N` bounds a short check; the default150 requires
actual natural death. The coordinator should retain the manifest before the
later cohort, use a new output directory and preserve all earlier evidence.
Assignments are exactly US900, CA901, GB902, AU903, FR904, DE905, ES906, IT907,
BR908, IN909, JP910 and ZA911. These reuse12 seeds; they do not increase the
separate120 annual-policy distinct-seed count.

Artifacts include a pinned `manifest.json`, exact250-template `catalogue.json`,
per-country birth metadata/checkpoint, `commands.ndjson`, `decisions.ndjson`,
`cold.ndjson`, `result.json`, final checkpoint and aggregate result. The trace
SHA256 is calculated from the actual newline-terminated sorted-key command
records; bigint values retain explicit `$dreamsBigInt` tags. The command-file bytes
must match the reported hash. Failures retain completed-country summaries,
actual source pins, original error and the last valid checkpoint when possible.
Output refuses an existing nonempty directory and stays outside both worktrees.
