# Natural hourly-work policy

Run `node tools/run-hourly-work-sweep.cjs`, redirecting stdout to a JSON file and
stderr to a separate progress/diagnostic log. A successful run exits0 and emits
one JSON object. Failures exit1, preserve completed-country records and write the
last valid encoded world and command trace to a separate temporary diagnostic.
Do not delete failed records when correcting a runner expectation.

This separate optional policy uses seeds900–911 across the twelve country packs.
It starts ordinary lives through normal creation, at a fixed initial birth date.
As with the existing work/leisure policy runners, it sets the birth-acknowledgement
flag before pure-engine play; actual store/SQLite/native acknowledgement remains
separate acceptance. Subsequent age, date, stats, funds, RNG and outcomes change
only through production engine commands.

The policy sets a healthy routine from age6. Countries rotate8/12/20contracted
hours;20-hour applications wait until the student's actual eligibility permits
them. Every country withdraws one reviewed interview and verifies unchanged RNG,
people, accounts, work history and hourly history, then verifies the yearly lock.
Responsible hiring responses use their actual bounded draws, preserving naturally
accepted and declined outcomes. It retains hourly work, applies again only after
job loss, requests eligible annual supervisor feedback/raises, and may book one
affordable eligible paid-leave holiday. Earned retirement uses actual service.
Annual decisions take their first available choice. Early death, hospital care,
job loss, refusal, unaffordable travel and lack of eligibility are not overridden.

Unanswered interviews, saved answers, raises, booking/retirement results, each year
with actual hourly payroll and final worlds undergo exact cold codec comparisons.
Each contract's receipts, cumulative pay rounding, paid/worked minutes, service
and work history are independently reconciled in the report. Output includes
initial terms, rate changes, attendance categories, naturally reached death ages,
commands, per-phase cold counts and final world hashes. Version tags come from
created worlds. Game, game/persistence and runner hashes are checked before and
after the run; game hashing matches the existing annual-sweep path convention.

These are scoped pure-engine cloud journeys. They add no distinct annual-policy
seed count, and do not establish SQLite/native behavior, all-choice coverage,
physical performance,120-year capacity, multiple generations or release readiness.
Elapsed time describes the whole host run, not button latency. Runtime integration
and raw result publication remain with the primary milestone verification.
